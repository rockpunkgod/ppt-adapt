# Cross-slide audio with a finite stop boundary

Backend: **hybrid**. OfficeCLI creates three editable pages and embeds the user's original WAV once on page 1; native PowerPoint COM sets media playback lifecycle. This is an increment to the separately verified trim/fade/bookmark recipes. It does not change them.

Source: BV1VTDGYsEmd P19, 1518–1587 s (the speaker labels it lesson 18). Real UI frames 1539/1557 s show cross-slide playback and a separate loop checkbox. Distributed screenshots and 3-second OCR samples are evidence samples, not continuous source viewing. No author music or presentation is bundled.

Use `scripts/media_lifecycle_build.py --officecli EXE --wav OWN_WAV --outdir FRESH_DIR`. Diagnostic acceptance below requires the 12-second constant-level, one-note-per-second WAV produced by `media_controls_assets.py`; arbitrary music can be used for production, but the pitch audit does not apply. Then use `media_lifecycle_polish.ps1 -InputDeck ... -OutputDeck FRESH.pptx -Evidence FRESH_DIR -StopAfterSlides 2`.

The native settings are PlayOnEntry true, PauseAnimation false, StopAfterSlides 2, LoopUntilStopped false. Two displayed slides means the music continues into page 2 and stops when page 3 enters in the tested straight progression. The original 12-second media stays embedded, with no trim or fade. Do not generalize this result to hidden slides, jumps, returning to earlier slides, or indefinite looping.

For verification, run `media_lifecycle_record.ps1 -Deck ... -Evidence FRESH_DIR -Ffmpeg EXISTING_EXE -Seconds 8`, followed by `media_lifecycle_analyze.py --evidence FRESH_DIR`. Recording uses the shared C03 window helper and process-scoped WASAPI helper from the same scripts directory. It captures the PowerPoint **process tree**, not an individual document: coordinate exclusive playback and play only the diagnostic media during capture. No microphone, default audio device, global volume, or Office preference is changed. Dependencies are not installed automatically. See `media-controls.md` for runtime requirements.

The recorder uses native COM `View.Next` twice. It verifies media lifecycle across real page transitions; it is not a physical mouse interaction test. PCM starts before Run and desktop capture after Run. Their clocks are logged separately; the stop tolerance is 0.45 s and is not a claim of precise synchronization. The continuity audit checks a fixed 1.2-second interior portion of page 2, preserves the same silence threshold, and independently tests stop timing and source-note progression. An earlier research analysis incorrectly included the stop edge in its continuous-play window; its false output is retained in research.

Research prototype and packaged fresh-forward both passed six runtime checks: correct pages 2/3, audible interior page 2, no pitch-clock restart, finite stop near page 3, stop before source natural end, and zero capture discontinuities/timestamp errors. Fresh proof: `verification/media-lifecycle-forward/`; native recording/contact sheet was viewed, source signal lasted 6.95 s of the original 12 s, stop was within 0.123 s of the logged page-3 return clock. Independent ZIP/native audit confirmed five checks including unchanged original WAV, no later-page audio, native settings, and `numSld=2`; schema validation passed. `media_lifecycle_verify.py` reproduces that audit. Do not treat a property readback or `numSld=2` alone as playback proof.

Official semantics: [StopAfterSlides](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.playsettings.stopafterslides), [PauseAnimation](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.playsettings.pauseanimation), [PlayOnEntry](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.playsettings.playonentry).

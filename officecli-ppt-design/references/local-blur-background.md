# Local native blur with common background coordinates

Backend **hybrid**: OfficeCLI creates the original foundation and assembles the background; PowerPoint COM creates actual native artistic Blur30 and genuine Fill.Background windows. The background uses the exact PNGcache generated by PowerPoint, not an external blur engine. Original unmodified image bytes and an editable native blur reference remain in the presentation.

Sources: BV1oPHgeiEgb P21 1962.9–2169.7 and P29 806–1015; BV1VTDGYsEmd P02 2031–2220; YouTube 9Ewb0Rd3P3E 2:27:21–2:29:09. Requested caption/OCR segments were read, actual operation frames inspected including P21 2069 Illustrator Gaussian38.8px, P29 836/1003local strokes, P02 2190PowerPointartisticblur, YouTube8864/8911native blur/background fill. Sources differ: Adobe Gaussian glyph blur and a passing reference to motionblur do not establish their equivalence to PowerPoint's native Artistic Blur30.

Tested atom: source photo duplicated and blurred in PowerPoint; blurred snapshot forms full-slide background, original clear picture sits above; shapes use **slide background fill**. Every window samples the same world-coordinate background, so moving it reveals the correct new region. It does not stretch a separate image into each shape. White outline is an original diagnostic boundary; the source's white inner-shadow frost styling is not claimed by this minimum atom.

```
pwsh -File scripts/local_blur_export.ps1 -Deck FRESH_FINAL/local-blur.pptx -Evidence FRESH_PNGS

```

Use fresh outputs, existing OfficeCLI/PowerPoint/PowerShell7/Python and FFmpeg; nothing is automatically installed. Production adaptation replaces the diagnostic image consistently across original/blur reference/background, keeps the same crop/size/placement, and regenerates the cache. Do not merely replace the clear foreground while leaving an old blur snapshot.

Native [PictureEffects.Insert](https://learn.microsoft.com/en-us/office/vba/api/office.pictureeffects.insert) with [msoEffectBlur=2](https://learn.microsoft.com/en-us/office/vba/api/office.msopictureeffecttype) creates a real Radius30pictureeffect. Native save recordsa14:artisticBlur, originalWDP layer and PNGrendercache. The bridge copies that exact PowerPoint-produced cache into the slidebackground. **The background is a regenerable snapshot, not a live Background.Fill blur parameter.** Native effect is editable on the reference picture. Procedural diagnostic image generation is material preparation, not an external-render recipe.

Important implementation evidence: standarda:blur directly underblip validated but rendered a blank picture in this environment. Native Background.Fill.PictureEffects returned an apparently detached defaultRadius10 and did not persist30. Both negative branches remain research-only. Do not ship those paths or call a blank image successful blur because highfrequency drops to0.

## 白色内阴影霜边

玻璃视觉先要有真正的局部模糊，再在面板内侧加柔和照明。沿用原有制作链，在build和verify命令增加`--frost`；polish、bridge、export和analyze保持原调用。新分支去掉诊断白描边，给四个背景填充窗口写入真实`a:innerShdw`：白色、100%不透明、Blur20pt、距离0、方向0。它没有把面板整体涂白，也没有用外发光或硬描边代替霜边。默认不传参数仍是原诊断稿及原验收范围。

```powershell
python scripts/local_blur_build.py --officecli EXE --outdir FRESH_BASE --frost
powershell -File scripts/local_blur_polish.ps1 -InputDeck FRESH_BASE/local-blur.pptx -OutputDeck FRESH_NATIVE.pptx -Evidence FRESH_NATIVE_LOG
python scripts/local_blur_bridge.py --input FRESH_NATIVE.pptx --officecli EXE --outdir FRESH_FINAL
python scripts/local_blur_verify.py --deck FRESH_FINAL/local-blur.pptx --original FRESH_BASE/original-coordinate-checker.png --report FRESH_JSON --frost
```

导图和像素检查沿用上面的命令。在原生界面读取的内阴影参数为白色、Blur20、透明度0、偏移0；保存时PowerPoint省略默认零距离/方向属性，不能据属性缺省认定阴影丢失。结构核验仍需真正innerShdw、白色和20pt，不只检查菜单读值。

四个窗口在两个位置分别检查：原有12项模糊/共享坐标/清晰外部像素标准不变且全部通过，新分支另核四项内阴影/无描边结构。对同稿去掉内阴影的原生对照，四条平直上边缘在内侧2/8/16/32px的增亮依次下降，32px处回到0；外侧与中心差异均为0，保存重开的原生PNG逐像素相同。圆角霜边另外目视检查，不用平直边缘量测代证任意轮廓。

## 字形的全体／局部 Gaussian 虚化

backend：**external-render**。这是不同于上面原生Artistic Blur的具体实现：复用`stroke_depth_geometry.py`的原创四笔“木”路径，只对所选对象的alpha做显式Gaussian卷积，再由OfficeCLI将透明PNG与其余清晰原生路径组合。原始轮廓和原文留在稿内；虚化层是可重建图片，不是继续可打字的字体或原生Gaussian效果。没有重写已有笔画、Multiply或背景模糊配方。

选择虚化范围先于调参数：整字退后用于引导主次；局部虚化只选择一笔或一个部件，剩余轮廓维持清晰，保留阅读骨架。不要在整字模糊图上再盖完整清晰字，那会变成辉光；局部效果中要移除该笔的清晰副本。样稿的虚化左撇在其余三笔后面，避免交点的模糊覆盖清晰横竖。

使用已有Pillow/NumPy环境和本机OfficeCLI：

```powershell
python scripts/glyph_gaussian_build.py --officecli EXE --outdir FRESH_OUT --sigma 12
powershell -File scripts/layout_story_native.ps1 -InputDeck FRESH_OUT/glyph-gaussian.pptx -OutputDirectory FRESH_NATIVE
```

生成器同时保留可重建alpha源、Gaussian图层和参数。当前600×600路径域以4倍超采样生成源alpha，`sigma`以该600像素域计；一维核`exp(-x²/(2σ²))`归一化，截断到4σ并补透明留白，分别沿x/y卷积。RGB保持恒定，只滤alpha，深浅底色都不会因把透明黑色一起模糊而出现黑边。此sigma不能直接视为Illustrator或Photoshop半径，也不能按源视频38.8px数值机械套到不同尺寸。

已独立测过默认σ12：两类源/结果alpha总量相对误差<0.025%，重心位移<0.001像素，x/y方差增量约141.23–142.41（离散核方差143.87，差异来自8位alpha量化）。PPT实际嵌入PNG字节与生成源一致；全字效果不含对应清晰路径，局部效果保留其余三条原生轮廓。三张原生导图、深浅底边缘及六个实播状态已复看，文字可读；原生保存重开逐像素一致，未选参考轮廓区域不变。23秒本机播放以5次方向键走1→2→3→2→3→2，返回正常、0额外输入。见[三页可编辑作品](../../examples/glyph-gaussian/README.md)。这是静态视觉配方，不新增动效通过声明。

来源资格：BV1oPHgeiEgb P21/P29，播放量564564。本轮Ego Lite复核18个视频元素帧：P21 2069秒明确选中字母i并显示Gaussian38.8px；2120秒显示拆分后的g下部单独Gaussian；P29 820秒仅左偏旁虚化、836–1003秒拆分复合字形并选择部件、1015秒可见局部虚实结果。Watch尝试P21字幕，来源无可用字幕，未下载音频或启用转写；以实际操作画面为本次视觉证据，不声称连续正常速度看完整节。方向性Motion Blur尚无完整操作证据，不能从本Gaussian样稿升级为verified。

范围是原创四笔轮廓、默认σ12及当前构图。其他sigma、任意字体自动拆笔、字孔或复杂自交、不同alpha颜色处理需按输入另验；此实现不证明Adobe算法/像素等价，也不据原生Artistic Blur的不同就断言PowerPoint原生永远无法实现其他Gaussian方案。

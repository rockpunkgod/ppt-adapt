# 整套演示：从表达目的到实际画面

这份指南帮助当前Agent作出设计与制作选择。已有配方继续负责具体技术；不另建制作引擎、审美评分表或报告流程。

## 每套作品独立构思，让随机产生新选择

默认每个新任务都从本次内容重新设计。先理解表达目的，再随机探索适配的艺术方向与视觉变量：字体性格与搭配、主辅色、空间比例、构图语法、图像或原生视觉主体，以及动效的速度与组织方式。可以在几个临时想到的合适方向中随机选择或重新组合；这些方向不是固定模板库。随机探索后用设计判断修正，留下真正适合这次演示的方案。无需建设随机引擎、风格数据库或唯一性评分系统。

面对没有指定美术方向的开放需求，先尝试两到三个明显不同的方向，每个方向做一个封面和一个承载主要信息的代表内容页，再用PowerPoint原生导图并排比较。差异要涉及字体形态、构图逻辑、空间关系和动效语法；只换颜色不算另一个方向。无需先做三套完整PPT，也不把候选页或选择说明塞进正式演示。允许自主推进时，根据实际画面的表达清晰度、辨识度与整套展开潜力选择一项；用户明确要求先选方案时再等待选择。方向明确的改稿和局部调整直接制作。

独特性要落在画面上：同一主题再次制作，也应重新构思视觉主体、字体关系、构图和连续场景，不能只给旧稿换文案、换颜色。已能看到近期作品时，主动避开其反复使用的封面、三栏卡片、图表样式和动效套路；无需为了证明唯一性读取所有历史作品，也不承诺数学意义上的永不重复。

复用配方的对象机制、坐标方法与可靠接口，重新设计其内容、比例、色彩、组合与叙事位置。示例配色、字体、素材和页面顺序都不是默认答案。不用凑齐效果清单来代替设计。

随机探索在整套艺术方向和局部创意选择上发生。方向确定后，共用字体角色、色彩语义和空间语言；每页依据信息关系自由变化，章节可以有意转调。事实、数据、阅读顺序、品牌要求及对象身份不能随机修改。用户指定模板或视觉规范时，遵从该约束，在允许的空间内创造变化。不要把随机性写成页面上的声明或用它解释明显的设计问题。

## 内容决定艺术方向

先读真实内容，找出观众、场景、核心主张和结束后的行动。现场演讲给画面与口述分工，阅读稿保留必要上下文；同一内容可能需要完全不同的密度。先将每页压成一个论点和一个主体画面，通读它们是否形成问题、证据、推论与行动。页数、目录和章节由内容决定。

项目或产品介绍先回答“它帮助谁完成什么”，再选择能让观众直接判断的证据：具体输入、一次完整任务、实际作品、可编辑对象或真实操作。让用户看到价值如何发生，再用制作机制解释成果如何实现。概念作品可以用于能力示范，但不能冒充客户成果；没有实际生成对照结果时，不编造“普通AI生成效果”来衬托项目。能力数量与制作流程只能提供背景，不能替代作品本身。

用两三句话定下具体方向：例如“强调可靠工程的产品演示：墨色与冷白、大幅产品细节、清楚的无衬线层级、慢速连续移动”；或“文化项目提案：暖纸、克制衬线、照片与题记、留白和静态阅读”。方向要能解释素材、字形、色彩和运动选择。需要比较时看少量明显不同的方向，随后选一个推进；不强制每次多方案评审。

技术主题可以用强对比、大字号、3D、异形遮罩与镜头感；社区服务、人物故事或严肃证据也可以大胆设计，但表达语气须与内容相符。不要自动套黑金、蓝紫渐变、发光圆环或全白卡片；也不要把“克制”解释成所有页面都只有标题和三段文字。

## 形成共同语言，保留构图自由

- **字体**：先分标题、正文、数据与标签角色，再选字形。一个家族可借字号/字重形成层级，也可用展示字体与阅读字体搭配。中文与Latin分别确认可用字体；用真实最长标题与正文试排。大字的字距、两行标题的行距、数字与单位的基线需要单独调整。课程的形态矩阵是比较候选的方法，不是打分器。见[字体与基础设计](typography-foundations.md)。
- **网格与比例**：保持可辨认的版心、边线与间距语法，让主体有足够面积。按信息关系选非对称双栏、全屏主体、编辑式文字、对比、时间关系、图表或复杂场景。重复单元先调好一个，再按图标/标题等语义锚点复制；替换每份文案后仍看实际折行，不能靠“框没溢出”略过孤立标点。见[网格与间距](grid-spacing-methods.md)。
- **色彩**：根据主题、品牌和情绪建立背景、文字、强调、数据语义色。高对比不等于高饱和；主色不必铺满整页。主体照片或产品本身可以提供色彩，图表中同一语义跨页保持同色。章节换底色时重新看文字、图表和媒体边缘。
- **素材与视觉主体**：产品介绍要让观众看到产品或具体使用过程；软件可用真实截图或明确标为概念的可编辑界面，硬件用产品照片、模型或合法准备的渲染。图像应承担证据、情境或解释，不能拿无关科技背景代替产品。没有真实数据、客户或性能结果就不编造证明。
- **视觉层级**：为每页决定第一眼、第二眼和补充信息。通过面积、明暗、位置、距离、字重或运动建立顺序；不要让标题、图标、图表、装饰同时争主角。清晰数据和必要条件优先保留，放不下时改结构、补页或将解释放入备注。

不要把网页专属的CSS像素、手机断点、hover、滚动限制、颜色禁令或固定字数搬成PPT硬规则。PPT中可以有图片说明、来源、章节停顿和必要的空间运动；字号、配色和版式服从当前演示，而非参考库的个人偏好。

## 用整套节奏组织变化

创意不只发生在选风格时。规划全稿时，把每页的论点、主要画面、阅读视角与转场关系一起看：有的页面用一个判断停住观众，有的让信息形成关系，有的让数据成为主角，有的进入具体空间或展示作品。字号、比例、构图、密度与运动强度随这些任务变化，不按固定的“两栏→三卡片→大数字”循环。

让关键页面有独立的视觉构思，选择与内容有关的隐喻、主体或空间关系；安静的说明页负责铺垫，章节变化负责转向。相同元素可以从整体变成细节、从概念变成作品，保留可辨认的身份而改变观看方式。复看全稿缩略图与关键实播时，优先重做机械重复的页面和缺乏作用的“漂亮页”，不要靠给每页追加特效制造变化。

开场明确主题并留下视觉记忆；中段用合适的证据和解释推进；关键处安排对比、展开或连续状态；结尾给出清楚的行动。让密集页、主体大图、关键数字、安静文字和章节页形成呼吸。共同字体、色彩语义与图形语言保持身份，布局可随页面职责变化。

连续场景应保留观众的心智地图：相同产品、窗口、轨道或图表在下一状态有明确对应。普通页面默认采用适合内容的柔和衔接；需要解释空间变化时使用Morph、视差、路径或Zoom。有意的直接切换应服务于明确的停顿或强调，不让缺省转场造成无意硬切。进入动作只帮助阅读，不能让观众等待文字出现；一条时间线上始终有明确焦点。没有叙事目的的自动循环、抖动或逐字入场应去掉。

## 让相邻页面和页内动作顺滑衔接

每对相邻页都考虑注意力如何交接。构图不同、没有共同对象时，优先用短而柔和的淡化；同一场景的展开、姿态或镜头变化保留真实对象身份，再用Morph等连续方式连接。大面积明暗或底色变化适当缓和亮度过渡，不把随机艺术方向延伸成随机转场清单。文字不同的标题和不相关图表不强行变形；处理重影、意外配对与文字拉伸。

页内运动同时安排起步、经过与停住。需要位移时设置合适的加减速，避免匀速启动后骤停；分组揭示可以短暂重叠，让阅读连续而不挤在同一时刻。时长根据运动距离、信息量和讲述节奏决定，延长所有动画不能代替调顺轨迹和时间关系。

入场前保留可理解的画面，不让整页正文等一次多余点击才出现，也不在新页面留下只有分隔线或空框的等待状态。真正需要讲解停顿的点击应有明确的信息单位，揭示完成后留出阅读时间。

用原生PowerPoint连续播放前后页，查看开始、中段与结束，确认没有闪白、跳位、意外空白、重影和突然改变的运动方向；需要返回的场景再看返回路线。顺滑与内容清晰一起判断，静态截图、转场名称和时长回读都不能证明实际衔接已经做好。

## 自然组合现有配方

先确定页面骨架与主体，再选择必要处理，最后决定是否跨页连续。下面是可调整的制作思路，不是需要逐一完成的组合清单。

|表达需要|组合制作方法|优先复用|
|---|---|---|
|一句重要判断成为记忆点|字体角色与字距 → 网格/留白 → 局部创意标题；正文仍保持可编辑|`type_build.py`、`build_layout_methods.py`、字体/文字相关参考|
|让观众看清产品及工作过程|准备真实主体 → 大幅构图 → 必要裁切/遮罩 → 相邻状态保同一对象做Morph/视差|`build_morph.py`、`build_components.py`与[连续状态](morph-patterns.md)|
|数据一步步支持判断|原生图表与正确坐标 → 结论/重点 → 按系列或类别揭示；讲述顺序与点击顺序一致|[图表构建](chart-build.md)、`chart_build_*`；有精修需要才用既有`polish_timing.ps1`|
|展示空间、结构或产品姿态|合法模型/已有原生资产 → 场景与文字分层 → 模型姿态或场景位移 → 适当文字入场|[3D场景](model3d.md)、`build_morph.py --mode 3d-template`；已有能力边界不变|
|让较长内容可自主进入和返回|先分章节 → 清楚的导航层级 → 原生Section/Summary Zoom → 与章节入口连续|[Section Zoom](section-zoom.md)、[Summary Zoom](summary-zoom.md)，按原配方保返回与重复进入行为|

制作时解决冲突：把字体/色彩收回共同语言；空间不够就改比例、重排或分组；多个动画争同一目标就删去多余动作或改时序；Morph先对准对象身份、状态与名称；OfficeCLI和COM修改同一文稿时先保存关闭再交接。内容正确与完整性、可读性、视觉一致性、动效、装饰按此顺序取舍。无需把这些判断变成独立规则引擎。

## 边做边看，最后原生播放

先看最能代表方向的页面：封面、复杂内容页、关键连续场景。把实际原生画面与探索稿、当前方向或合适参考并排比较，检查主体是否足够大、字形与语气是否相符、阅读顺序和图片焦点是否成立。动画要看中间帧与节奏，静态截图不能证明播放质量。再看全稿缩略图，找重复构图、密度突变和没有推进的信息。随制作直接调整，不等到最后才处理明显问题；按最影响表达的少数问题精修，不追逐审美分数或建立评审平台。

最后做减法：逐个判断卡片、边框、强调色、图形和动画是否帮助内容表达，删去无意义的容器、重复标签、过度强调和相同的重复入场。保留必要的分组、阅读线索与交互提示，不因某种样式常见就一律禁止。参考[Distinctive AI Design](https://github.com/houxin0010/distinctive-ai-design/blob/main/SKILL.md)的探索、真实画面比较与减法思路；在本项目中由当前Agent保持整套上下文完成，不迁入其网页检查脚本、多Agent评审或评分机制。

设计不只是加法。优先用更大胆的艺术方向与更精准的取舍提升制作水准，不以特效数量衡量作品。先让关键静态画面有足够的表现力，再把动效留给需要解释的关系、连续变化与讲述节奏；已有动效若分散焦点，就缩短、合并或删除。

最后用本机PowerPoint打开并播放整套，确认文字与素材正常、关键动画能完整执行、最后一页能停留。涉及原有特殊配方时沿用其必要验证；普通设计改稿不新建测试平台或大型验收报告。未经实际播放的新组合不沿用单项配方的通过声明。

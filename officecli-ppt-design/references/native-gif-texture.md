# 原生动画导透明 GIF，再做活动纹理

Backend **hybrid**。OfficeCLI创建可编辑动画源及展示页，PowerPoint COM分组/动画/Intersect，真实PowerPoint界面导出动态GIF；填充表示修复只改OOXML，不重新编码像素。执行工具随技能存放在`scripts/native_gif_*`；仓库成品与复现命令在`examples/native-gif-texture`。

## 制作方法

1. 先制作原生矢量纹理。相同中心的方框组合后追加Spin90°与Grow130%，各2秒、WithPrevious、AutoReverse，平滑开始/结束各1秒。COM Size用130，不用1.3；后者会生成1.3%的目标。源页去转场。
2. 用PowerPoint“导出→创建动态GIF”，特大1080p、背景透明、每页0秒自动时长，范围只含源页。静态Export(GIF)、CreateVideo后外部转GIF或程序GIF不能代替本步骤。质量/范围/透明选项操作后恢复。
3. 把原生导出的GIF作为真正图片插回。复制并精确重叠一份原生花瓶轮廓，原底色轮廓留在下方；先选GIF、再选轮廓，GIF为PrimaryShape执行Intersect3。保留动画源，之后改纹理从源重新导出。
4. 保存重开看几轮。必须同时看到内部纹理在动、轮廓不动、轮廓外不漏色。另放同GIF裸图作快速对照；图片仍引用GIF或文件有多帧都不能单独证明裁后能播放。

## 本机裁后静止的修复

同页对照中，裸原生GIF与已有GIF正常，相交结果静止。隔离裁剪和几何后确认：保留相交结果的自定义几何与位置，将图片`srcRect`等价改成`stretch/fillRect`可恢复本例动态。单纯删crop虽会动，却把整个GIF压进轮廓包围盒，画面比例错误。

设srcRect为l/t/r/b，100000表示100%。横向剩余宽W=100000−l−r，纵向H=100000−t−b；目的填充范围为`l'=-100000*l/W`、`r'=-100000*r/W`、`t'=-100000*t/H`、`b'=-100000*b/H`，四舍五入到整数。将这些值写进原空fillRect并移除srcRect；**不动custGeom、xfrm、GIF字节和底层轮廓**。负值令原图延展到裁形边界外，再由真实几何裁切。存在复杂填充、非正裁剪或空区域时不要套用此有限修复。

`native_gif_repair.py`只处理已实际Intersect、正裁剪、空fillRect的受测情况。经PowerPoint再次保存，字段与动态仍保持。不能由本例推导所有PowerPoint版本都需要此修复；若裁后本来正常，按实际作品验证即可。

## 已实测范围

发布源从头制作并原生导出1920×1080透明GIF，99帧/98不同画面、3.96秒编码周期；最终PPTX保存重开后18秒实际播放、19个分布帧及225个裁后采样帧通过。独立花瓶边界外未见纹理；与裸图对应内容在1像素容差下最低匹配约99.99%，并保持后续循环。GIF字节与相交曲线在修复及原生再保存前后不变，无外部孔罩或视频替代。

原生动画源仍是可编辑矢量/时间轴；交付GIF本身的每一帧不是PPT中的独立矢量。换素材、轮廓、编码或播放环境后重新预览。此配方不包含指定对象触发GIF、任意GIF处理或复杂纹理滤镜，不修改既有GIF/PNG菜单的通过范围。
